    Create `src/app/(auth)/login/` directory, then create actions.ts with two Server Actions.

    The file must start with `'use server'` directive at the top.

    ```typescript
    'use server'

    import { createClient } from '@/lib/supabase/server'
    import { revalidatePath } from 'next/cache'
    import { redirect } from 'next/navigation'

    export async function login(formData: FormData) {
      const supabase = await createClient()

      const { data, error } = await supabase.auth.signInWithPassword({
        email: formData.get('email') as string,
        password: formData.get('password') as string,
      })

      if (error) {
        return { error: error.message }
      }

      revalidatePath('/', 'layout')
      redirect('/dashboard')
    }

    export async function register(formData: FormData) {
      const supabase = await createClient()

      const { data, error } = await supabase.auth.signUp({
        email: formData.get('email') as string,
        password: formData.get('password') as string,
        options: {
          emailRedirectTo: `${process.env.NEXT_PUBLIC_SITE_URL || 'http://localhost:3000'}/auth/callback`,
        },
      })

      if (error) {
        return { error: error.message }
      }

      // When email confirmation is disabled in Supabase dashboard,
      // signUp returns an active session. Redirect to dashboard.
      if (data.session) {
        revalidatePath('/', 'layout')
        redirect('/dashboard')
      }

      // If email confirmation IS enabled (user didn't disable it yet),
      // return success message instead of redirect
      return { success: true, message: '请检查邮箱并点击确认链接' }
    }

    export async function logout() {
      const supabase = await createClient()
      await supabase.auth.signOut()
      revalidatePath('/', 'layout')
      redirect('/login')
    }
    ```

    Critical constraints:
    - `login` uses `signInWithPassword` with email+password from FormData
    - `register` uses `signUp` with emailRedirectTo pointing to /auth/callback
    - `logout` calls `signOut` then redirects to /login
    - Each function independently calls `createClient()` to re-verify auth (anti-pattern prevention)
    - `revalidatePath('/', 'layout')` before redirect ensures Next.js re-renders with fresh session state

    Create `src/app/auth/callback/` directory, then create route.ts.

    This Route Handler handles Supabase auth callbacks -- email confirmation links, password reset links, and OAuth redirects. Supabase redirects the user here with an auth code, which is exchanged for a session.

    ```typescript
    import { createClient } from '@/lib/supabase/server'
    import { NextResponse, type NextRequest } from 'next/server'

    export async function GET(request: NextRequest) {
      const { searchParams, origin } = new URL(request.url)
      const code = searchParams.get('code')
      // next is the redirect path after successful auth code exchange
      const next = searchParams.get('next') ?? '/dashboard'

      if (code) {
        const supabase = await createClient()
        const { error } = await supabase.auth.exchangeCodeForSession(code)
        if (!error) {
          // Session established via email link (password reset, email confirm)
          return NextResponse.redirect(`${origin}${next}`)
        }
      }

      // If no code or exchange failed, redirect to login
      return NextResponse.redirect(`${origin}/login`)
    }
    ```

    Key constraints:
    - Route must be a GET handler (Supabase redirects with query params)
    - Uses `exchangeCodeForSession` to convert the auth code to a session
    - On success, redirects to the `next` param (defaults to /dashboard)
    - On failure or no code, redirects to /login
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| FormData -> Server Actions | User input from forms must be validated; Server Actions are entry points independent of page-level auth |
| Auth code -> Session exchange | Supabase provides auth code via query param; must be exchanged server-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Tampering | login Server Action | mitigate | Independently calls createClient() to verify session; uses Supabase's signInWithPassword (bcrypt + JWT, no custom auth logic) |
| T-01-06 | Tampering | register Server Action | mitigate | Uses Supabase signUp with server-side emailRedirectTo validation; no user role escalation possible via client tampering |
| T-01-07 | Tampering | logout Server Action | mitigate | Calls signOut to invalidate session server-side; redirect to /login prevents access to protected routes |
| T-01-08 | Spoofing | Auth callback route | mitigate | exchangeCodeForSession validates the auth code with Supabase server; invalid codes are rejected |
</threat_model>
