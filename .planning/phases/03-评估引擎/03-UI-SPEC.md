## Page Structure (D-06 — Locked)

The result page (`/result`) has three vertical bands rendered in a single-column layout.
No tabs, no modals, no sidebar.

```
┌─────────────────────────────────────┐
│  BAND 1 — Score Banner              │
│  Overall score number + tier badge  │
├─────────────────────────────────────┤
│  BAND 2 — Dimension Cards           │
│  4 rows: label / progress bar / tag │
├─────────────────────────────────────┤
│  BAND 3 — Narrative + CTA           │
│  AI paragraph (plain text)          │
│  CTA button (full width)            │
└─────────────────────────────────────┘
```

Max content width: 640px, horizontally centered, padding 16px on each side.
Page background: gray-50 (matches existing assessment page and result placeholder).

Tier badge color map (text + border + background):

| Tier | Badge classes |
|------|--------------|
| 高度适配 | `bg-emerald-50 border border-emerald-200 text-emerald-700` |

## Component Inventory

### 1. ScoreBanner

File: `src/components/result/ScoreBanner.tsx`

Structure:
```
<section> — white card, rounded-xl, shadow-sm, p-6
  <p> — "您的创业适配评分" — text-sm text-gray-500
  <div> — flex items-end gap-3
    <span> — score number — text-4xl font-bold text-gray-900
    <span> — tier badge — see badge color map above, text-sm font-medium px-2 py-0.5 rounded-full border
  <p> — subtitle line based on tier (see Copywriting Contract) — text-sm text-gray-500 mt-2
```

Wishing-type display rule (resolves RESEARCH.md Open Question 1):
- If `is_wishing_type = true`: Display the numeric score with a `text-xs text-gray-400` note below: "（参考分数，综合适配等级以标签为准）".
- Score is never hidden — hiding it creates confusion when users compare. The note explains the discrepancy without accusation.

### 2. DimensionCard

File: `src/components/result/DimensionCard.tsx`

Structure (one row per dimension, stacked vertically with `mb-6` between rows):
```
<div> — mb-6
  <div> — flex justify-between mb-1
    <span> — dimension label — text-sm font-medium text-gray-700
    <span> — evaluation tag — text-sm text-gray-500
  <div> — h-2 bg-gray-100 rounded-full overflow-hidden
    <div> — h-full bg-blue-600 rounded-full — style={{ width: `${pct}%` }} — (inline style, NOT dynamic Tailwind class — see RESEARCH.md Pitfall 3)
```

Dimension order (top to bottom):
1. 弹性资金 (annualCapital, max 400 pts)
2. 投入金额 (investmentAmount, max 300 pts)
3. 投入时间 (weeklyTime, max 200 pts)
4. 预期回报 (expectedReturn, max 100 pts)

Evaluation tag text per dimension band (executor decides exact thresholds, these are tier-agnostic labels):

| pct range | Tag |
|-----------|-----|
| 80–100% | 充裕 / 充足 / 充分 / 合理 |
| 50–79% | 良好 / 适中 / 中等 / 偏高 |
| 20–49% | 偏低 / 不足 / 有限 / 偏高 |
| 0–19% | 不足 / 紧张 / 很少 / 过高 |

Each dimension uses its own contextually appropriate vocabulary:
- 弹性资金: 充裕 / 良好 / 偏低 / 不足
- 投入金额: 充足 / 适中 / 偏低 / 不足
- 投入时间: 充分 / 中等 / 有限 / 很少
- 预期回报: 合理 / 偏高 / 过高 / 极高 (inverted — lower expected return = better score)

### 3. NarrativeParagraph (no separate component needed — inline in result page)

Render as a `<p>` element within the bottom band:

### 4. ResultCTA

File: `src/components/result/ResultCTA.tsx`

Uses the existing `Button` component (`src/components/ui/Button.tsx`) with `variant="primary"`.

```tsx
<div className="mt-8">
  <Button variant="primary">
    {isWishingType ? '准备好后预约顾问' : '立即预约专属顾问'}
  </Button>

```

Button behavior in Phase 3: no actual payment/booking flow (Phase 4). The button renders as a disabled-looking placeholder OR a `mailto:` link. Executor chooses; a `mailto:` link is preferred to avoid dead interaction.

Destructive actions in Phase 3: none. No confirm dialogs needed.

### 5. Loading Skeleton (loading.tsx)

File: `src/app/(chat)/result/loading.tsx`

Render a skeleton matching the three-band layout:
- Band 1: `h-24 bg-gray-200 rounded-xl animate-pulse`
- Band 2: four `h-10 bg-gray-200 rounded animate-pulse` rows with `mb-4` between
- Band 3: `h-16 bg-gray-200 rounded animate-pulse` + `h-12 bg-gray-200 rounded-md animate-pulse mt-4`

No spinner icon. Tailwind `animate-pulse` only.

## Copywriting Contract

### Primary CTAs (D-08 — Locked)

| User tier | CTA button copy |
|-----------|----------------|
| 许愿型 (is_wishing_type = true) | 准备好后预约顾问 |
| 高度适配 | 立即预约专属顾问 |
| 中度适配 | 立即预约专属顾问 |
| 需要准备 (non-wishing) | 立即预约专属顾问 |

Note: 需要准备 non-wishing users get the positive CTA — only 许愿型 gets the gentle version (D-08 maps tier, not score).

### Score Banner Subtitle by Tier

| Tier | Subtitle copy |
|------|--------------|
| 高度适配 | 您的各项条件与创业要求高度匹配，建议尽快与顾问深入交流。 |
| 中度适配 | 您已具备一定的创业基础，顾问可帮助您找到最佳切入点。 |
| 需要准备 (non-wishing) | 当前阶段还有一些准备工作，打好基础会让创业之路更顺畅。 |
| 需要准备 (wishing-type) | 创业热情是好事，当前阶段建议先做好准备，时机成熟后再出发。 |

### Narrative Tone Anchors (D-07 — Locked)

These are tone constraints for the DeepSeek prompt, not literal copy. The AI generates the paragraph; these anchors define its register.

| User type | Tone | Anchor phrases (examples for prompt engineering) |
|-----------|------|--------------------------------------------------|
| 许愿型 | 温和劝退 — acknowledges enthusiasm, identifies specific mismatches, encourages preparation, no judgment | "您的创业热情令人钦佩" / "目前的预期回报率偏高，可能增加实际操作难度" / "建议先了解行业实际数据" |
| 高度适配 | 正面肯定 + 行动引导 | "您的各项条件配置非常扎实" / "这样的资源储备让您有更大的试错空间" / "建议尽快开始" |
| 中度适配 | 正面肯定 + 具体建议 | "您已经具备了创业的核心基础" / "在[薄弱维度]上做一些针对性准备" / "顾问可以帮您制定具体计划" |
| 需要准备 (non-wishing) | 诚实但建设性 | "目前的条件还需要一些时间积累" / "重点关注[最低子分维度]" / "这并不是放弃，而是更聪明的准备" |

Narrative paragraph length: 3–5 sentences. Must include at least one specific reference to the user's actual data (e.g., "您每年有 X 万的弹性资金"). Must NOT reference the numeric score directly in the paragraph (score is already visible in the banner).

### Empty State (no completed assessment)

Not shown to user — redirect to `/dashboard` immediately (handled in Server Component, not in UI).

### Error State (DeepSeek failure fallback)

If `ai_narrative` is null or empty in the persisted record, render this fallback paragraph:

| Tier | Fallback narrative |
|------|--------------------|
| 高度适配 | 您的各项创业条件表现出色，资金储备、时间投入和回报预期都在合理范围内。建议您尽快与我们的专属顾问沟通，制定具体的落地方案。 |
| 中度适配 | 您已具备良好的创业基础，部分条件还有进一步优化的空间。我们的顾问可以根据您的具体情况，帮助您找到最适合的创业路径。 |
| 需要准备 (non-wishing) | 创业是一段需要充分准备的旅程。目前来看，还有一些基础条件可以进一步夯实。建议先与顾问做一次初步沟通，了解您需要为哪些方面做准备。 |
| 需要准备 (wishing-type) | 创业热情是非常宝贵的资源，但合理的预期同样重要。目前建议您先深入了解所在行业的实际回报数据，调整预期后再做决策，这样创业成功的概率会大大提高。 |

## Accessibility Contract

- Score banner: wrap score number in `<p aria-label="综合评分 {score} 分">` for screen readers
- Tier badge: rendered as `<span role="status">` so screen readers announce it
- Progress bars: each `<div>` bar container gets `role="progressbar" aria-valuenow={pct} aria-valuemin={0} aria-valuemax={100} aria-label="{dimensionLabel} {pct}%"`
- CTA button: uses existing Button component which renders a native `<button>` — already accessible
- Page `<main>` landmark: present in existing result/page.tsx pattern — maintain it

Keyboard: no interactive elements except the CTA button. Tab order is linear (banner → bars are non-interactive → narrative → CTA).

Reduced motion: `animate-pulse` on skeleton is the only animation. Progress bar `transition-all` is a layout-side property (width) — acceptable as it is a one-time render, not a scroll animation. No `prefers-reduced-motion` override needed for this minimal animation surface.

Color contrast:
- `text-emerald-700` on `bg-emerald-50`: passes AA (verified by Tailwind palette contrast ratios)
- `text-amber-700` on `bg-amber-50`: passes AA
- `text-gray-600` on `bg-gray-100`: passes AA
- `text-white` on `bg-blue-600`: passes AA (4.5:1+)
